# Contributing

## Prerequisites

- Node 20+
- [yarn v1](https://classic.yarnpkg.com/lang/en/docs/install)

## Setup

```sh
yarn
yarn build
```

This installs all dependencies and builds output files to `dist/`.

## Code generation & releases

This SDK is generated by [Stainless](https://www.stainlessapi.com/).
Development happens on `main` in the private `privy-io/node-sdk-private` repo. The public
[`privy-io/node-sdk`](https://github.com/privy-io/node-sdk) repo is updated only when a
release is published, so its `main` matches the latest release. Releases are managed by
[release-please](https://github.com/googleapis/release-please); see
[RELEASING.md](./RELEASING.md) for how to cut and review a release.

### Contributing from the public repo

You can open pull requests against `main` in `privy-io/node-sdk`, but they aren't merged
there. A maintainer re-lands the change in the private repo with you as co-author and closes
your PR. The change ships in the next release. The failing `Public PR` check on your PR is
that reminder, not a problem with your change.

### Importing a public pull request (maintainers)

From a clone of `node-sdk-private`, with `N` set to the public PR number:

```sh
git fetch origin main
git fetch https://github.com/privy-io/node-sdk.git "pull/$N/head:public-pr-$N"
git switch -c "import/node-sdk-$N" origin/main
git diff "$(git merge-base origin/main "public-pr-$N")" "public-pr-$N" | git apply -3
```

`git apply -3` stages the change and leaves conflict markers where it can't apply cleanly.
Resolve them, then commit with the public PR's title and credit the author
(`git log -1 --format='%an <%ae>' "public-pr-$N"`):

```sh
git commit -m "<public PR title>" \
  -m "Imported from privy-io/node-sdk#$N" \
  -m "Co-authored-by: <author name> <author email>"
git push -u origin HEAD
```

Open a PR in `node-sdk-private` with the same `Imported from` and `Co-authored-by` lines in
the body, so they survive a squash merge. Then close the public PR with a comment that the
change was imported and will ship in the next release.

## Pull requests

PR titles **must** follow [Conventional Commits](https://www.conventionalcommits.org/) format:

```
type(optional scope): description
```

Allowed types: `feat`, `fix`, `docs`, `test`, `ci`, `refactor`, `perf`, `chore`, `revert`, `style`, `build`.

Examples:

```
feat: add wallet balance endpoint
fix(auth): handle expired tokens
chore: update dependencies
```

A CI check will block merge if the PR title does not match this format.

## Code structure

Most of the SDK is generated code. The following locations are safe to edit by hand:

- `src/lib/`
- `src/public-api/`

Manual edits persist across regeneration but may cause merge conflicts with changes from the generator.

## Development workflow

### End-to-end tests

End-to-end tests run against the staging environment. Create a `.env` file with `TEST_APP_SECRET` set, and optionally `TEST_APP_ID` and `TEST_API_URL`, then run:

```sh
yarn test:integration
```

### Lint & format

```sh
yarn lint
yarn fix
```

Formatting and linting use [prettier](https://www.npmjs.com/package/prettier) and [eslint](https://www.npmjs.com/package/eslint).

## Local development

To use a local version of this library from source in another project, install from git:

```sh
npm install git+ssh://git@github.com:privy-io/node-sdk.git
```

Or link a local clone:

```sh
# With yarn
yarn link
cd ../my-package
yarn link @privy-io/node

# With pnpm
pnpm link --global
cd ../my-package
pnpm link --global @privy-io/node
```
